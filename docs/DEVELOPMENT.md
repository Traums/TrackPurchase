# Разработка и релизы

[← На главную](../README.md)

## Окружение

Основная поддерживаемая сборка — Windows x64 с MSVC. Установите стабильный Rust и Visual Studio Build Tools с Desktop development with C++ и Windows SDK. build.rs ищет rc.exe в стандартном каталоге Windows Kits 10 и встраивает assets/icon.ico.

```powershell
cargo test --locked
cargo build --release --locked
```

Cargo.lock хранится в репозитории; при обновлении зависимостей включайте его в коммит.

## Структура

- `src/main.rs` — запуск, обработчики UI, состояние и сохранение.
- `src/logic.rs` — модели, расчёты, календарь, импорт / экспорт и тесты.
- `ui/app.slint` — основное окно и формы.
- `ui/widgets.slint` — компоненты интерфейса.
- `ui/theme.slint` — цвета, размеры и типографика обеих тем.
- `build.rs` — компиляция Slint и Windows-значок.

## Проверка изменений

CI запускает тесты и release-сборку на Windows. Перед PR проверьте обе темы, пустой список, длинные названия и формы. Изменения хранения должны сохранять совместимость со старыми JSON. Новые сценарии расчётов проверяйте тестами; к визуальным изменениям приложите скриншоты без личных данных.

## Выпуск версии

1. Обновите version в Cargo.toml и Cargo.lock, CHANGELOG.md и заметки в docs/releases/.
2. Дождитесь зелёного CI в main.
3. Создайте тег вида v0.1.0 на проверенном коммите и отправьте его в origin.
4. Workflow Release сверит тег с Cargo.toml, запустит тесты, соберёт Windows x64, упакует ZIP и создаст SHA256SUMS.txt.
5. Workflow создаст черновик релиза. Проверьте файлы, скачайте архив, проверьте запуск на Windows и опубликуйте.

Первый релиз может быть выпущен вручную из проверенной локальной release-сборки с теми же именами файлов. Не переносите опубликованный тег на другой коммит: исправления выпускаются новой версией.

## Платформы

Linux и macOS не проходят CI; готовые сборки не публикуются. Их поддержка требует отдельной проверки.
